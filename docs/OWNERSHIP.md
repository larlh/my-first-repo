# Propiedad de directorios

> Regla 2 del [prompt maestro](prompt/MASTER_PROMPT.md): **cada agente escribe solo dentro de sus
> directorios**. Un cambio fuera de ellos solo se hace si es aditivo y compatible (ver
> [CONTRACTS.md §14](CONTRACTS.md#14-cómo-extender-un-contrato)) y se declara en el informe; si
> no puede ser aditivo, no se hace: se reporta.

## Lo que no está en la lista anterior

Todo lo compartido pertenece al **arquitecto** (rol `architect`; lo custodia el orquestador
entre fases). Nadie más lo edita salvo con cambios aditivos declarados.

| Directorio / archivo                                                                                                                                                                                               | Dueño                             | Qué pueden hacer los demás                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/shared/` (contratos)                                                                                                                                                                                     | architect                         | Solo cambios **aditivos** (CONTRACTS §14), con test, declarados en el informe.                                                                                                               |
| `packages/db/` (esquema, migraciones, créditos, utilidades de test)                                                                                                                                                | architect                         | Columnas nuevas _nullable_ o con `default` + migración generada (`pnpm db:generate --name …`). Nunca editar una migración existente.                                                         |
| `packages/jobs/` (cola y servicios compartidos por API y worker: `startRender`, `resolveVoice`, `synthesizeCached`, URLs de archivo, webhooks…)                                                                    | architect                         | Si API y worker necesitan la misma lógica, va aquí: se propone como función nueva (aditiva) con test. No se duplica en `apps/`.                                                              |
| `packages/providers/src/{index,registry,env,errors}.ts`                                                                                                                                                            | architect                         | Añadir variables de entorno en `env.ts` (y en `.env.example`) es aditivo y está permitido a providers-speech / providers-ai.                                                                 |
| `packages/renderer/package.json`, `packages/providers/package.json`                                                                                                                                                | architect                         | Dependencias nuevas con `pnpm --filter <paquete> add`, declaradas.                                                                                                                           |
| `apps/api/src/` salvo `modules/<dominio>/`: `app.ts`, `server.ts`, `config.ts`, `types.ts`, `lib/`, `plugins/`, `testing/`, `modules/system/`, `modules/_template/`                                                | architect                         | Ayudantes nuevos en `lib/` solo si los usa más de un módulo; lo específico vive en el módulo.                                                                                                |
| `apps/worker/src/` salvo `jobs/<dominio>/`: `main.ts`, `bootstrap.ts`, `config.ts`, `context.ts`, `lib/`, `testing/`, `jobs/system/`                                                                               | architect                         | Igual que la API. `lib/render-status.ts` y `lib/avatar-status.ts` son la única vía para escribir estados terminales.                                                                         |
| `apps/web/` salvo `src/features/<feature>/`: `src/app/`, `src/lib/`, `src/ui/`, `src/components/`, `src/styles/`, `src/shell.ts`, `src/main.tsx`, configuración de Vite/Tailwind, `src/features/_example/`         | **web-shell** (agente `base-web`) | Los features nunca editan archivos compartidos: un feature es una carpeta (ver `apps/web/README.md`). | Raíz: `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `tsconfig.base.json`, `eslint.config.js`, `.prettierrc.json`, `.env.example`, `docker-compose.yml`, `docker/`, `scripts/`, `README.md`, `CLAUDE.md` | architect                         | `pnpm-lock.yaml` cambia solo a través de `pnpm add`. | `docs/ARCHITECTURE.md`, `docs/CONTRACTS.md`, `docs/OWNERSHIP.md`                                                                                                                                                   | architect                         | Quien añade una ruta, cola o clave de storage añade su línea en CONTRACTS.                                                                                                                   |
| `docs/prompt/MASTER_PROMPT.md`                                                                                                                                                                                     | propietario del producto          | No se edita.                                                                                                                                                                                 |

## Zonas de contacto (dónde dos roles se tocan y quién decide)

| Zona                                                                     | Regla                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/stock-assets/assets/avatars/` y `src/photoreal-avatars.ts`     | Paquete de **content**, pero los retratos stock fotorrealistas (`real_<slug>`) los **genera neural-engine** con el motor: aporta los PNG y sus entradas de catálogo como cambio aditivo declarado. Los ids publicados no se renombran.                            |
| `packages/renderer/src/avatars/photo.ts` → `photoAvatarPlacement`        | La escribe avatar-artist, pero la usa `render-frame.ts` (renderer-core) para el clip neuronal: cambiar su geometría mueve a la vez vista previa y exportación; no se duplica en ninguno de los dos lados.                                                         |
| `packages/renderer/src/subtitle-draw.ts` → `drawSubtitleCue`             | De renderer-core; la consume worker-aux (traducción con subtítulos incrustados). Su firma no cambia.                                                                                                                                                              |
| `packages/renderer/src/media.ts`                                         | De renderer-core; la consumen web-studio (reproductor) y worker-render (decodificación). `renderFrame` debe seguir pasando por ella.                                                                                                                              |
| `apps/worker/src/jobs/render/` ↔ `packages/providers/src/lipsync/`       | worker-render llama a `providers.lipsync.animate` con rutas propias; **providers-ai** mueve los archivos al directorio del motor (`createEngineJobDir`). worker-render no conoce `AVATAR_ENGINE_WORK_DIR`.                                                        |
| `packages/providers/src/{lipsync,portrait}/` ↔ `services/avatar-engine/` | El contrato es `packages/shared/src/avatar-engine.ts` (architect). Cambios solo aditivos; el motor debe funcionar si ignora un campo opcional nuevo.                                                                                                              |
| Póster de borradores y plantillas                                        | `apps/api/src/lib/poster.ts` (architect) lo llaman api-content (`videos`, `templates`).                                                                                                                                                                           |
| Arranque de render                                                       | `startRender` (packages/jobs, architect) lo llaman api-content (`videos`, `public-v1`) y worker-aux (`batch`). Ninguno reimplementa moderación, límites ni cobro.                                                                                                 |
| Síntesis de voz                                                          | `synthesizeCached` (packages/jobs) lo llaman api-content (`voices`), api-ai (`interactive`), worker-render y worker-aux (`translation`).                                                                                                                          |
| Borrado en cascada de datos de una persona                               | api-identity (`consent` → revocar) y api-ai (`photo-avatars`, `voice-clones` → borrar) deben eliminar lo mismo: fila, prefijo de storage, voz externa y asset de origen. Si hace falta un ayudante común, va a `apps/api/src/lib/` como cambio aditivo declarado. |

## Puertos para servidores de prueba

Los tests no abren puertos (la API se prueba con `app.inject`; el worker con cola en memoria o
con un prefijo de Redis aleatorio). Para pruebas manuales cada encargo indica sus puertos; los
de desarrollo por defecto son API `4000`, web `5173`, motor `8090`, Postgres `5432`, Redis `6379`.
